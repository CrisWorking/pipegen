What this audit can't see
  - pipegen checks that a tool runs on the right trigger and can fail the build; it doesn't check
    the tool's other settings.
  - Workflows limited by `paths:` or `paths-ignore:`, and jobs or steps with an `if:` condition,
    show as partial: pipegen can't tell when they run.
  - A tool and a test joined on one line, like `{ tool; [[ … ]] } || true`, can hide a failing tool,
    and pipegen may still count it as covered (rare).
  - Commands inside `bash -c '…'` or a quoted `"$(…)"` aren't read, so a tool run there shows as
    partial or missing.
  - A `runs-on` set by an expression is read as Linux.
  - Tools inside shell functions, and jobs whose matrix includes Windows, show as partial.
  - Very large repos show some checks as unknown: past 200 workflow files, 100 jobs in a workflow,
    200 steps in a job or action, 100 local workflows and actions followed, 16 MB of run text,
    50,000 steps visited in all, 100,000 tool findings, 10,000 folders with runs, or 5,000 services.
  - Reusable workflows from other repos, and actions from your own account, can't be looked inside:
    those checks show as unknown.
  - Shell tricks such as `trap … EXIT`, `alias`, or a function named like the test tool aren't
    modelled, so a repo built to fool the audit could make a check look covered.
  - A local action or reusable workflow that calls another local one isn't followed past the first
    level, so those checks show as unknown.
  - `tox` counts as your own test run whatever environments its config lists: pipegen doesn't read
    tox's env_list.
  - A tox or nox run whose environments a TOX… or NOX… variable in the job picks (like TOXENV from a
    matrix) shows as partial: pipegen doesn't read the variable's value, so it can't tell if the
    tests run.
  - Variables that change what runs (SKIP for pre-commit, TOX… and NOX… for tox and nox,
    NPM_CONFIG_DRY_RUN) aren't seen when an action from another repo sets them, or when a step
    writes them under a name built while it runs.
  - A pre-commit hook pinned to a commit SHA (`rev:`) isn't checked to be a commit of the hook's own
    repo, so it could come from a fork.
  - pipegen knows the PyPI publish action up to v1.14.3: a newer release pinned by its commit SHA
    shows as partial until pipegen is updated.
  - A test or lint script whose runner pipegen doesn't know (like `node test.js`) is trusted by its
    name: pipegen only lowers it when the script clearly does nothing or can't fail.
  - Coverage minimums in JS or TS config files (like jest.config.js or vitest.config.ts) are read as
    text: pipegen finds the setting but can't run the file, so it can't confirm the minimum.
  - Renovate presets (`extends`) aren't followed, so a setting that comes from a shared preset isn't
    seen.
  - Repo settings on GitHub (required checks, secret scanning, the default token permissions) aren't
    read, so pipegen can't say whether they are already on.
  - A workflow without a `permissions:` block gets the repo's default token permissions, a setting
    pipegen can't see.
  - A deploy workflow that uses no secret and no write grant isn't seen as a release.
  - Network egress control (blocking unexpected traffic from release jobs) is only partly read on
    larger runners.
  - Environment variables set by third-party actions aren't seen, so a check one of them turns off
    can show as covered.
  - pipegen can't check yet that an ESLint config reads .vue, .svelte and .astro files (the parsers
    and plugins come in v0.2): such a repo never shows a clean pass for ESLint.
  - The quick secret check on the files on disk looks only for a few secret formats (private keys,
    some token formats, JWTs, passwords in connection strings); it doesn't read `name = value`
    lines, such as an API key or a password set in code or in a .env file, so it is not a secret
    scan.
  - Kubernetes manifests are looked for only in YAML under folders named k8s, kubernetes, manifests,
    deploy, helm or charts (and a Chart.yaml anywhere), so manifests kept elsewhere, like infra/,
    aren't seen.
